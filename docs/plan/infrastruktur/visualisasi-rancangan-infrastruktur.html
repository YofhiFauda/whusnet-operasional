Contoh visual dari analisa-gap-peta-infrastruktur.md. Data di bawah fiktif. Bagian yang bertanda ◆ usulan belum ada di kode, sisanya sudah ada atau sedang dikerjakan (belum di-commit).

Satu node, tiga lapis data

LAPIS 1 · POSISI

Di mana titik ini dalam jaringan

Baris network_nodes. Ditambatkan ke POP (anchor_pop_id) atau berada di bawah node hulu (parent_id). Tidak menyimpan model atau SN perangkat.

LAPIS 2 · KAPASITAS

Port, dan siapa yang menempatinya

network_node_ports + network_port_assignments. Satu port berisi pelanggan, node hilir, atau label manual, lengkap dengan riwayat pasang/lepas.

LAPIS 3 · BARANG GUDANG

Perangkat fisik yang terpasang

Aktif: SN berstatus DEPLOYED (current_network_node_id). Pasif: saldo infrastructure_balances (qty/roll). Ganti perangkat tidak mengubah posisi.

Contoh pohon: WHUSNET → Jetis → C1

Pilih node di tab mana pun. Detailnya, termasuk peta port, barang Gudang, dan kasus terkait, tampil di panel samping.

Susunan pohon mengikuti data pops yang sebenarnya: WHUSNET (pusat) → Jetis/Sandya (cabang) → C1/D1 (Mini POP). Node jaringan menempel ke POP lewat anchor_pop_id atau ke node lain lewat parent_id. Port uplink (ungu) tidak menentukan induk. Port itu hanya mencatat jalur fisik, misalnya backbone mana yang menyuplai Cabang Jetis.

Penjaga yang harus ada sebelum UI dikejar

L1 · Chassis OLT

Node olt_chassis di bawah Mini POP

SN chassis di-deploy ke node ini. Kartu jadi anak chassis, bukan ditambatkan langsung ke Mini POP.

L2 · Aset lama

Registrasi Aset Terpasang

SN dibuat langsung DEPLOYED dengan ledger sendiri dan permission terpisah, tanpa task palsu.

L3 · Kompatibilitas

Kategori barang ↔ tipe node

Kartu PON tidak bisa di-deploy ke ODP. Tabel aturan dikelola admin, kosong berarti bebas.

L4 · Status

acceptsNewAttachments()

Node Rencana/Gangguan/Nonaktif menolak deploy dan pelanggan baru. Nonaktif hanya kalau node sudah kosong.

L5 · Jumlah port

Port node = sumber kebenaran

Spesifikasi barang hanya saran isian saat membuat node, tanpa sinkron otomatis.

L6 · Temuan baru

Port tujuan harus anak node pemilik port

parent_id dan sambungan port bisa saling bertentangan: ODP berada di bawah ODC-1, tapi port ODC-2 yang menunjuknya. Aturan: target.parent_id = port.node_id, kecuali uplink antar-POP (switch agregasi → OLT, backbone → cabang).

Kunci keputusan

Chassis OLT (L1) diputuskan sebelum kerja olt_slots di-commit. Jawab pertanyaan lapisan pusat, OLT di Cabang, dan cara isi aset lama.

Fondasi aturan

Aturan susunan tipe, port kartu = port PON (16, bukan 128), status Rencana/Aktif/Gangguan/Nonaktif (L4), aturan L6, lepas kartu.

2

Barang Gudang di tiap level

Node chassis (L1), Registrasi Aset Terpasang (L2), kompatibilitas (L3), panel aktif/pasif di halaman detail node.

3

Akses lanjut

Tipe Feeder (port = core, warna serat dari nomor core), hitung ONT per PON secara berantai.

4

Lapisan pusat (opsional)

Core/Layanan/Backbone di POP Pusat, uplink lintas cabang lewat port, kapasitas Gbps, tinggi rack dari atribut Item.

5

Tampilan

Kanvas topologi, inventaris dengan urutan utilisasi, pencarian SN/pelanggan/alamat.
